# ASCII 风格人脸识别签到系统 MVP 方案

## 1. 项目定位

### 1.1 项目名称

基于 OpenCV 与人脸特征编码的 ASCII 风格智能签到系统

### 1.2 项目简介

本项目面向课堂签到场景，设计并实现一个具有创意视觉表现的人脸识别签到系统。系统使用摄像头采集用户人脸图像，通过图像预处理、人脸检测、特征提取和相似度匹配完成身份识别，在识别成功后自动生成签到记录，并以 ASCII 字符风格实时展示摄像头画面和识别结果。

### 1.3 项目目标

- 完成学生人脸注册和样本管理
- 完成摄像头实时人脸检测与识别
- 完成自动签到与防重复打卡
- 完成 ASCII 风格实时显示
- 完成签到记录保存与基础出勤统计

## 2. MVP 功能范围

### 2.1 必做功能

1. 人脸注册
2. 实时识别
3. 自动签到
4. 重复签到拦截
5. ASCII 风格预览
6. 签到记录保存
7. 基础出勤统计

### 2.2 暂不纳入 MVP 的功能

- Web 端完整后台

- 云端数据库
- 复杂权限系统

说明：以上功能可以作为后续优化项，用于答辩时说明扩展空间，但不建议放入首版实现范围。

## 3. 与人工智能课程知识的结合点

本项目虽然以签到业务为外在形式，但核心技术流程与人工智能课程知识高度相关，主要体现在以下几个方面：

### 3.1 数据预处理

- 摄像头采集原始图像
- 图像缩放，降低计算量
- 灰度化或颜色空间转换，减少冗余信息
- 去噪与亮度均衡，提高检测稳定性

对应课程知识：数据预处理、特征准备、噪声抑制。

### 3.2 计算机视觉中的目标检测

- 从整幅图像中定位人脸区域
- 将人脸区域从背景中分离出来
- 为后续识别提供稳定输入

对应课程知识：图像识别、目标检测、视觉感知。

### 3.3 模式识别与特征提取

- 将人脸图像转换为特征向量
- 使用已注册人脸特征库进行匹配
- 根据距离或相似度完成身份判定

对应课程知识：特征提取、模式识别、相似度计算、分类决策。

### 3.4 决策逻辑

- 识别成功后判断是否已签到
- 控制签到状态和输出结果
- 将识别结果转化为业务决策

对应课程知识：规则推理、阈值判定、结果输出。

### 3.5 数据分析

- 对签到记录进行统计
- 计算出勤人数、缺勤人数、签到时间分布
- 形成可视化分析结果

对应课程知识：数据分析、行为模式挖掘、结果解释。

## 5. 系统模块设计

MVP 建议分为五个核心模块。

### 5.1 人脸注册模块

职责：

- 输入学生姓名、学号
- 采集或上传人脸照片
- 检测照片中是否存在清晰单人脸
- 提取特征并保存

输入：

- 摄像头图像或图片文件
- 学生基本信息

输出：

- 学生信息
- 人脸样本或特征编码

### 5.2 实时识别模块

职责：

- 读取摄像头视频流
- 检测当前帧中的人脸
- 提取当前人脸特征
- 与特征库进行匹配

输入：

- 视频帧
- 人脸特征库

输出：

- 识别姓名
- 识别置信结果
- 陌生人标记

### 5.3 签到决策模块

职责：

- 判断识别结果是否可信
- 判断是否重复签到
- 生成签到状态
- 写入签到记录

输出状态示例：

- 签到成功
- 已签到，请勿重复打卡
- 未识别到有效身份
- 当前用户未注册

### 5.4 ASCII 渲染模块

职责：

- 将视频帧转换为灰度矩阵
- 按亮度映射到字符集合
- 输出字符风格预览
- 叠加识别状态和姓名信息

推荐字符集示例：

`@ # S % ? * + ; : , .`

设计目的：

- 增强项目创意展示效果
- 作为可视化层与识别模块解耦

### 5.5 数据记录与统计模块

职责：

- 保存签到时间、姓名、学号、状态
- 按日期查询签到结果
- 统计签到人数、缺勤人数、重复签到次数
- 生成基础报表

## 6. 系统整体流程

系统主流程如下：

1. 启动摄像头并加载已注册用户信息
2. 对视频帧进行预处理
3. 检测视频帧中的人脸区域
4. 提取人脸特征并与数据库比对
5. 输出识别结果
6. 若识别成功，则进入签到判定
7. 若当天未签到，则写入记录
8. 同时将视频帧转换为 ASCII 风格显示
9. 用户可查看签到结果和统计信息

## 7. 底层实现逻辑

这一部分是答辩文档中的重点，建议重点讲清楚。

### 7.1 图像采集与预处理逻辑

目的：

- 提高后续检测和识别的稳定性
- 降低实时计算压力

流程：

1. 使用 OpenCV 调用摄像头采集视频帧
2. 按固定比例缩放图像
3. 进行颜色空间转换
4. 根据需要进行灰度化、均衡化或去噪

可答辩表述：

在实时视觉任务中，原始图像通常包含光照波动和背景噪声，因此需要先进行预处理，以减少无关因素对识别结果的影响。

### 7.2 人脸检测逻辑

目的：

- 从视频帧中定位待识别对象

流程：

1. 输入预处理后图像
2. 调用 OpenCV 检测器得到人脸框坐标
3. 裁剪出候选人脸区域

可答辩表述：

人脸检测负责回答“画面中哪里有人脸”，识别负责回答“这是谁”，两者在逻辑上属于不同阶段。

### 7.3 人脸识别逻辑

目的：

- 将当前人脸与已注册身份进行匹配

流程：

1. 对检测到的人脸区域提取特征
2. 将该特征表示为向量
3. 与数据库中的特征向量逐一计算距离
4. 取最小距离对应身份作为候选结果
5. 若最小距离小于阈值，则识别成功
6. 否则判定为陌生人

可答辩表述：

人脸识别的关键不在于直接比较两张图像像不像，而在于比较两张人脸在特征空间中的距离是否足够接近。

### 7.4 签到判定逻辑

目的：

- 将识别结果转化为业务动作

流程：

1. 若识别失败，则不给签到
2. 若识别成功，则查询当前日期是否已有该用户记录
3. 若没有，则写入签到表
4. 若已有，则提示重复签到

这部分体现：

- 状态机思维
- 规则驱动决策
- 人工智能结果到业务逻辑的落地过程

### 7.5 ASCII 渲染逻辑

目的：

- 将普通视频流转化为创意显示效果

流程：

1. 将图像缩小到字符网格大小
2. 计算每个网格块的亮度
3. 按亮度映射到不同密度字符
4. 将字符矩阵拼接为输出界面

说明：

该模块不是识别核心，但可以作为项目创新性和可视化表达的重要部分。

## 11. 答辩重点建议

答辩时不要把重点放在“界面很好看”，而应把重点放在以下几个问题：

1. 为什么这个项目属于人工智能应用
2. 图像预处理、人脸检测、人脸识别分别在做什么
3. 为什么识别需要阈值判定
4. 签到系统如何避免重复打卡

6. 数据记录和统计如何体现智能分析能力

- 能稳定演示
- 能讲清底层逻辑
- 能体现人工智能课程知识与创新表达

如果后续进入开发阶段，建议优先实现顺序如下：

1. 人脸注册
2. 实时识别
3. 自动签到
4. ASCII 风格预览
5. 签到记录与统计
