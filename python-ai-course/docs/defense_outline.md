# 答辩文档提纲

## 1. 项目背景

传统课堂签到通常依赖人工点名或二维码签到，存在效率低、代签风险和数据统计不便等问题。本项目面向智慧校园场景，设计一个基于人脸识别的智能签到系统，并加入 ASCII 风格实时视觉展示，提升项目演示效果和交互辨识度。

## 2. 项目目标

- 使用摄像头实时采集人脸图像
- 通过 OpenCV 完成人脸检测和图像预处理
- 通过 OpenCV LBPH 人脸识别模型完成人脸身份识别
- 根据识别结果自动生成签到记录
- 对签到数据进行基础统计分析
- 使用 ASCII 风格界面展示实时画面和识别状态

## 3. 系统流程

```text
摄像头采集
-> 图像预处理
-> 人脸检测
-> 特征提取
-> 特征匹配
-> 阈值判定
-> 签到决策
-> 识别事件日志/签到结果保存
-> 数据统计
-> ASCII 可视化展示
```

## 4. 核心模块

### 4.1 图像采集模块

使用 OpenCV 调用本机摄像头，持续读取视频帧。视频帧作为后续人脸检测、识别和 ASCII 渲染的统一输入。

### 4.2 图像预处理模块

对原始视频帧进行缩放和颜色空间转换。缩放可以减少计算量，颜色空间转换可以满足不同识别算法对输入格式的要求。

### 4.3 人脸检测模块

人脸检测负责判断画面中是否存在人脸，并返回人脸区域位置。该步骤回答的是“画面中哪里有人脸”。

### 4.4 人脸识别模块

人脸识别负责将检测到的人脸转换为局部二值模式直方图特征，并交给 LBPH 模型预测身份。模型会返回候选标签和置信度，置信度低于阈值时才判定为同一人。

### 4.5 签到决策模块

签到决策模块根据识别结果判断是否写入记录。如果当天该学生已经签到，则返回重复签到状态，避免重复写入。

本项目将“识别过程”和“签到结果”分开保存：`event_log.csv` 记录 success、duplicate、unknown、no_model 等识别事件，`attendance.csv` 只保存真正生效的签到结果。这样既能避免重复签到污染业务表，也能保留足够的数据用于分析识别质量。

### 4.6 ASCII 渲染模块

ASCII 渲染模块将视频帧转换为灰度矩阵，再根据亮度值映射为不同密度的字符，形成字符风格实时画面。

### 4.7 数据统计模块

系统将签到记录和识别事件保存为 CSV 文件，并统计签到人数、重复签到次数、未知人脸次数、出勤率和识别成功率，为后续出勤分析提供基础。未检测到人脸属于正常空帧状态，不计入异常，也不写入事件日志。

## 5. 人工智能课程知识结合

### 5.1 数据预处理

摄像头采集到的原始图像包含背景、光照变化和噪声。系统先对图像进行缩放和颜色转换，体现了人工智能任务中“先处理数据，再进行模型判断”的基本流程。

### 5.2 特征提取

系统不是直接比较两张图片，而是先把人脸区域转换为灰度图，再提取局部二值模式直方图特征。LBPH 通过描述局部纹理分布来区分不同人脸。

### 5.3 模式识别

当系统拿到当前人脸特征后，LBPH 模型会输出最接近的标签和对应置信度。这体现了模式识别中的分类思想。

### 5.4 阈值判定

系统不会只根据“最接近”就直接认定身份，而是设置置信度阈值。只有当置信度低于阈值时，系统才认为识别可信，否则判定为陌生人。

### 5.5 数据分析

签到结果和识别事件可以被进一步统计，用于计算出勤情况、重复签到情况、未知人脸情况和识别成功率，体现了人工智能应用中从感知、决策到分析解释的完整过程。

## 6. 创新点

- 使用 ASCII 风格实时展示摄像头画面
- 将人脸识别结果与签到业务逻辑结合
- 支持重复签到拦截
- 支持签到数据统计，为后续出勤分析提供基础

## 7. 演示步骤

1. 注册测试学生的人脸信息
2. 启动实时签到程序
3. 摄像头识别已注册学生
4. 系统显示签到成功
5. 再次识别同一学生，展示重复签到拦截
6. 移开人脸，展示 no_face 是正常空帧状态
7. 查看签到记录和识别事件日志
8. 查看数据分析页面的出勤率、重复签到和识别成功率
