# 系统设计说明

## 1. 总体架构

系统采用本地 Python 后端 + React 前端的演示架构。Python 负责 AI 算法、数据存储和 API，前端负责摄像头交互、ASCII 展示和结果查看。

整体链路：

```text
浏览器摄像头 / 本地图片
-> 图像预处理
-> Haar 人脸检测
-> LBPH 人脸识别
-> 阈值判断
-> 签到决策
-> SQLite 保存签到和事件
-> 前端展示记录与统计
-> 决策树训练与风险分析
```

## 2. 技术栈选择

| 技术 | 用途 | 选择原因 |
| --- | --- | --- |
| Python | 后端与 AI 逻辑 | 适合快速实现图像处理和机器学习流程 |
| OpenCV | 摄像头、人脸检测、LBPH 识别 | 轻量、可本地运行、无需 GPU |
| SQLite | 本地数据存储 | 零部署，适合课程项目演示 |
| scikit-learn | 决策树风险分析 | 轻量、可解释、适合小样本演示 |
| joblib | 保存模型 | scikit-learn 常用模型持久化方式 |
| React + Vite | 前端演示 | 交互效率高，便于展示注册、识别和统计 |
| unittest | 后端测试 | 标准库测试工具，运行简单 |

## 4. 数据设计

SQLite 保存主要业务数据：

| 表 | 作用 |
| --- | --- |
| `attendance` | 真正生效的签到结果 |
| `event_log` | 识别过程事件 |
| `students` | 学生基础信息 |
| `grades` | 学生成绩 |
| `ml_training_samples` | 决策树训练样本 |

运行时文件：

- `data/encodings/labels.json`：学生和 LBPH label 映射。
- `data/encodings/lbph_model.yml`：人脸识别模型。
- `data/models/student_risk_model.joblib`：学生风险模型。
- `data/exports/*.csv`：导出的签到和事件 CSV。

提交时只跟踪 `.gitkeep` 等占位文件，运行数据不进 Git。

## 5. 人脸识别流程

### 5.1 注册

1. 前端采集 3 张人脸样本。
2. 后端校验每张图片中恰好有 1 张人脸。
3. 灰度化、直方图均衡化并归一化到固定尺寸。
4. 为学生分配或复用 label。
5. 保存样本并重训 LBPH 模型。

### 5.2 识别

1. 摄像头采集实时帧。
2. 前端生成 ASCII 画面并把画面发送到后端。
3. 后端检测人脸。
4. LBPH 模型预测 label 和 confidence。
5. confidence 小于等于阈值时判定为可信身份。
6. 写入签到或重复签到事件。

## 6. 签到和事件分离

`attendance` 表只保存真正生效的签到结果；同一学生同一天多次识别时，系统保留一条有效签到记录，并把重复识别作为过程事件处理。

`event_log` 表保存识别过程，包括：

- `success`
- `duplicate`
- `recognized`
- `unknown`
- `no_model`

这样既能保证业务表干净，也能分析识别成功率和异常原因。

## 7. 智能分析设计

智能分析模块使用决策树进行学生风险分类。输入特征包括：

- 近 30 天出勤率。
- 近 7 天迟到次数。
- 近 30 天缺勤次数。
- 近 30 天重复签到次数。
- 历史平均成绩。
- 最近一次成绩变化。

输出结果：

- 风险等级：低风险、中风险、高风险。
- 风险分数。
- 模型置信度。
- 状态摘要。
- 教师处理建议。

由于没有真实长期班级数据，系统提供可重复生成的演示数据，用于展示完整机器学习流程。

## 8. 前端设计

前端页面包括：

| 页面 | 作用 |
| --- | --- |
| 实时签到 | 摄像头预览、ASCII 画面、识别状态 |
| 用户注册 | 采集 3 张人脸样本并注册 |
| 数据中心 | 查看签到记录和识别事件，导出 CSV |
| 系统分析 | 展示出勤率、识别成功率和事件分布 |
| 智能分析 | 生成演示数据、训练模型、查看风险报告 |

API 调用集中在 `frontend/src/api.ts`，页面组件只关心展示和交互。

- 事件统计。
- 旧 CSV 兼容升级。
