# 前端逻辑设计

本项目的前端样式可以独立设计，当前文档只约定页面职责、数据流和交互逻辑。

## 1. 页面结构

### 1.1 实时签到页

核心区域：

- ASCII 摄像头预览
- 当前识别身份
- 当前签到状态
- 当前时间
- 操作按钮：开始、暂停、退出

状态：

- 未检测到人脸
- 识别中
- 签到成功
- 已签到
- 未注册用户

### 1.2 人脸注册页

核心区域：

- 学号输入
- 姓名输入
- 摄像头拍照或图片上传
- 注册结果提示

交互流程：

1. 输入学号和姓名
2. 采集人脸图片
3. 后端检测是否存在有效人脸
4. 保存人脸特征
5. 返回注册成功或失败原因

### 1.3 签到记录页

核心区域：

- 日期筛选
- 姓名筛选
- 签到记录表格
- CSV 导出按钮

字段：

- 日期
- 时间
- 学号
- 姓名
- 状态

### 1.4 数据分析页

核心区域：

- 今日签到人数
- 重复签到次数
- 用户签到排行
- 签到趋势图预留位

## 2. 前后端接口草案

### 2.1 注册接口

```text
POST /api/register
```

请求数据：

```json
{
  "user_id": "2026001",
  "name": "张三",
  "image": "base64 image"
}
```

返回数据：

```json
{
  "success": true,
  "message": "注册成功"
}
```

### 2.2 签到状态接口

```text
GET /api/attendance/live
```

返回数据：

```json
{
  "name": "张三",
  "user_id": "2026001",
  "status": "success",
  "time": "08:30:12"
}
```

### 2.3 统计接口

```text
GET /api/stats
```

返回数据：

```json
{
  "total_records": 10,
  "status_counts": {
    "success": 8,
    "duplicate": 2
  }
}
```

## 3. 给样式实现者的说明

视觉方向建议：

- 整体风格偏科技感和终端感
- ASCII 画面作为第一视觉中心
- 识别状态需要清晰突出
- 不要让装饰样式遮挡签到状态
- 数据页面以可读性优先

前端只需要按以上页面逻辑实现样式，后端接口可在后续开发时对接。
