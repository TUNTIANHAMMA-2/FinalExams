# 演示流程脚本

本文档用于答辩现场演示。建议演示时间控制在 5 到 7 分钟，重点展示 AI 识别链路和智能分析闭环。

## 1. 演示前准备

确认内容：

- Python 依赖已安装：`pip install -r requirements.txt`。
- 后端 API 可以启动：`python -m app.main serve`。
- 前端依赖已安装并可启动：`npm run dev`。
- 浏览器允许摄像头权限。
- 如果现场摄像头不可用，准备已有截图或使用命令行 `demo-checkin` 验证数据链路。

推荐打开材料：

- `../README.md`
- `../答辩.md`
- [项目理解速览](./project-understanding.md)
- [系统设计说明](./system-design.md)

## 2. 开场介绍

建议 30 秒说明：

“本项目是一个面向课堂签到场景的 AI 应用。它用 OpenCV 完成人脸检测和 LBPH 人脸识别，识别成功后自动签到，同时记录识别事件，并进一步用决策树模型结合考勤和成绩生成学生状态风险报告。”

## 3. 演示步骤

### 步骤一：启动后端 API

命令：

```bash
python -m app.main serve
```

讲解点：

- 后端提供注册、样本校验、识别签到、记录查询、统计和智能分析接口。
- 默认 API 地址是 `http://127.0.0.1:8765`。

### 步骤二：启动前端

命令：

```bash
cd frontend
npm run dev
```

讲解点：

- 前端是浏览器演示界面。
- 通过 API 调用 Python 后端。

### 步骤三：注册学生人脸

展示页面：用户注册。

操作：

1. 输入学号和姓名。
2. 打开摄像头。
3. 采集 3 张有效人脸样本。
4. 提交注册。

讲解点：

- 后端要求每张样本中恰好有 1 张人脸。
- 3 张样本覆盖角度和光照变化。
- 注册后重训 LBPH 模型。

### 步骤四：实时签到

展示页面：实时签到。

操作：

1. 启动摄像头。
2. 展示 ASCII 实时画面。
3. 让已注册学生进入画面。
4. 观察识别结果和签到状态。

讲解点：

- 前端展示 ASCII 画面。
- 后端执行检测、识别和阈值判断。
- confidence 越小越相似，低于阈值才认为识别可信。

### 步骤五：重复签到拦截

操作：同一学生再次进入画面。

讲解点：

- 系统返回 duplicate。
- `attendance` 不重复写入。
- `event_log` 保留重复识别事件，用于分析识别过程。

### 步骤六：查看数据中心

展示页面：数据中心。

讲解点：

- 查看有效签到记录。
- 查看识别事件日志。
- 导出 CSV。
- 说明签到结果和识别过程为什么分开保存。

### 步骤七：查看系统分析

展示页面：系统分析。

讲解点：

- 出勤率。
- 识别成功率。
- 事件分布。
- 用户签到次数。

### 步骤八：智能分析

展示页面：智能分析。

操作：

1. 生成演示班级数据。
2. 训练决策树模型。
3. 刷新学生风险分析。

讲解点：

- 演示数据由后端生成并写入 SQLite，前端展示的是同一套业务表中的真实结构化数据。
- 决策树使用出勤、迟到、缺勤、重复签到、成绩等特征。
- 输出低/中/高风险和教师建议。

## 4. 收尾总结

建议 30 秒总结：

“这个项目展示了一个完整 AI 应用流程：图像采集、预处理、人脸检测、人脸识别、阈值决策、业务签到、数据统计和机器学习风险分析。它把模型输出接入真实业务流程，而不只是停留在算法演示。”
