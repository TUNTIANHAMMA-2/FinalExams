# 项目理解速览

## 1. 一句话介绍

ASCII 风格人脸识别签到系统是一个面向课堂签到场景的人工智能期末项目，使用 OpenCV 完成人脸检测和 LBPH 人脸识别，并结合机器学习模型生成学生状态风险分析报告。

## 2. 要解决的问题

传统课堂签到常见问题：

- 人工点名耗时。
- 二维码或口头签到存在代签风险。
- 签到记录难以自动统计。
- 识别过程和业务签到结果容易混在一起。
- 教师难以及时发现出勤和成绩异常学生。

本项目通过人脸识别自动签到，并把签到、识别事件、成绩和机器学习分析整合到同一套本地系统中。

## 3. 项目定位

本作业关注 AI 应用落地能力，项目不仅展示识别算法，也展示算法如何接入签到业务、数据统计和智能分析流程。项目包含：

- Python 后端和命令行入口。
- OpenCV 人脸检测与 LBPH 识别。
- SQLite 本地数据库。
- React + Vite 前端演示界面。
- 决策树学生风险分析。
- 单元测试和答辩文档。

核心源码目录：

- `../app/`：后端、AI、存储和 API。
- `../frontend/`：浏览器演示界面。
- `../tests/`：后端和智能分析测试。
- `../data/`：运行时数据目录，提交时只保留必要占位文件。

## 4. 用户角色与使用路径

主要角色：

| 角色 | 作用 |
| --- | --- |
| 学生 | 注册人脸、完成签到 |
| 教师 / 管理者 | 查看签到记录、识别事件、统计分析和风险报告 |
| 系统 | 检测人脸、识别身份、写入数据、生成分析结果 |

典型使用路径：

1. 启动 Python API 服务。
2. 启动 React 前端。
3. 在注册页面采集 3 张有效人脸样本。
4. 系统训练 LBPH 人脸识别模型。
5. 在实时签到页面打开摄像头。
6. 系统检测人脸并识别身份。
7. 识别成功后写入签到记录，重复签到会被拦截。
8. 查看记录、事件日志和统计分析。
9. 生成演示班级数据并训练决策树风险模型。
10. 查看学生状态评估报告。

## 5. 核心功能模块

| 模块 | 作用 |
| --- | --- |
| 图像采集 | 调用摄像头或接收前端图片数据 |
| 图像预处理 | 缩放、灰度化、直方图均衡化 |
| 人脸检测 | 使用 Haar Cascade 定位人脸 |
| 人脸识别 | 使用 LBPH 模型匹配学生身份 |
| 签到决策 | 写入成功签到并拦截同日重复签到 |
| 事件日志 | 保存 success、duplicate、unknown、no_model 等过程事件 |
| 数据统计 | 计算出勤率、识别成功率和事件分布 |
| 智能分析 | 使用决策树预测低/中/高风险学生 |
| 前端界面 | 注册、实时签到、数据中心、系统分析、智能分析 |

## 6. 项目亮点

1. AI 链路完整：从采集、预处理、检测、识别到业务决策。
2. 识别事件和签到结果分表保存，便于分析识别质量。
3. 每名学生采集 3 张样本，提高注册稳定性。
4. 前端使用 ASCII 风格展示实时画面，增强演示辨识度。
5. 使用决策树把签到数据扩展为学生状态预警。
6. 提供测试，验证签到拦截、事件统计和智能分析。

## 7. 答辩重点表达

可以按“课堂签到问题、AI 处理流程、业务数据设计、前端演示、机器学习分析、测试验证”展开。重点说明本项目不只是调用摄像头，而是完成了从感知、识别、决策、存储到分析的闭环。
