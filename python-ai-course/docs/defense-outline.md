# 答辩提纲

本文档可用于制作 PPT 或组织口头汇报。建议 8 到 10 页，汇报控制在 6 到 8 分钟。

## 1. PPT 结构建议

### 第 1 页：项目标题

标题：ASCII 风格人脸识别智能签到系统

内容：

- 课程：《人工智能基础与应用》
- 技术：Python、OpenCV、LBPH、SQLite、React、决策树
- 汇报人、班级、日期

### 第 2 页：项目背景

内容：

- 人工点名效率低。
- 二维码签到存在代签风险。
- 签到数据统计不便。
- 教师难以及时发现异常学生。

### 第 3 页：系统目标

内容：

- 人脸注册。
- 实时识别。
- 自动签到。
- 重复签到拦截。
- 识别事件记录。
- 数据统计。
- 学生风险智能分析。
- ASCII 风格实时展示。

### 第 4 页：总体流程

内容：

```text
摄像头采集 -> 预处理 -> 人脸检测 -> LBPH 识别 -> 阈值判断 -> 签到 -> 统计 -> 风险分析
```

讲解重点：

“系统体现了从感知到决策再到分析的完整 AI 应用链路。”

### 第 5 页：人脸识别设计

内容：

- Haar Cascade 检测人脸。
- 每名学生采集 3 张样本。
- LBPH 提取局部纹理特征。
- confidence 阈值判断。

### 第 6 页：数据存储设计

内容：

- SQLite 表。
- `attendance` 保存有效签到。
- `event_log` 保存识别过程。
- labels 和模型文件。
- CSV 导出。

### 第 7 页：前端演示设计

内容：

- 注册页面。
- 实时签到页面。
- 数据中心。
- 系统分析。
- 智能分析。
- ASCII 实时画面。

### 第 8 页：机器学习智能分析

内容：

- 演示数据生成。
- 训练样本。
- 6 个特征。
- 决策树分类。
- 风险等级和教师建议。

### 第 9 页：测试与质量

内容：

- API 参数测试。
- 重复签到测试。
- 事件统计测试。
- CSV 兼容测试。
- 智能分析测试。
- 前端 lint 和 build。

### 第 10 页：总结与展望

内容：

- 完成 AI 识别与业务闭环。
- 不足：真实数据较少、抗照片攻击能力有限。
- 后续：活体检测、更强识别模型、真实班级数据、图表分析。

## 2. 口头汇报版提纲

1. 项目是什么。
2. 解决什么课堂签到问题。
3. 系统有哪些功能。
4. 人脸检测和识别如何实现。
5. 签到结果和事件日志为什么分开。
6. 前端如何展示和调用后端。
7. 决策树智能分析如何设计。
8. 测试覆盖了哪些关键逻辑。
9. 总结收获和不足。

## 3. 3 分钟压缩版

1. 背景：课堂签到人工成本高，普通签到方式可能代签。
2. 功能：注册人脸、实时识别、自动签到、防重复、统计和风险分析。
3. AI：Haar 检测人脸，LBPH 识别身份，决策树预测学生风险。
4. 数据：SQLite 保存签到、事件、学生、成绩和训练样本。
5. 展示：React 前端展示 ASCII 画面、记录和分析结果。
6. 总结：项目完成了一个可演示的 AI 应用闭环。

## 4. 答辩中容易被问到的点

- 为什么选择 LBPH？
- 为什么每名学生采集 3 张样本？
- confidence 阈值如何理解？
- 为什么要分开保存签到记录和识别事件？
- no_face 为什么不写入事件日志？
- 决策树特征有哪些？
- 演示数据和真实数据的区别是什么？
- 项目有哪些不足和后续优化？

这些问题的参考回答见 [答辩常见问答](./defense-qa.md)。
