# ASCII 风格人脸识别签到系统答辩

## 1. 项目简介

本项目是《人工智能基础与应用》期末项目，主题为 ASCII 风格人脸识别智能签到系统。系统使用 OpenCV 完成人脸检测和 LBPH 人脸识别，结合本地 SQLite 数据库保存签到结果和识别事件，并提供 React 前端展示注册、实时签到、记录查询、统计分析和学生风险智能分析。

## 2. 已完成的核心功能

- 人脸注册：每名学生采集 3 张有效人脸样本。
- 人脸检测：使用 Haar Cascade 检测画面中的人脸区域。
- 人脸识别：使用 OpenCV LBPH 模型进行身份匹配。
- 自动签到：识别成功后写入签到记录。
- 防重复签到：同一学生同一天重复识别不会重复写入业务签到表。
- 识别事件日志：保存 `success`、`duplicate`、`recognized`、`unknown`、`no_model` 等识别过程。
- 数据统计：计算出勤率、识别成功率、用户签到次数和事件分布。
- 智能分析：使用决策树模型结合考勤和成绩数据输出学生风险评估报告。
- 前端展示：提供注册、实时签到、数据中心、系统分析和智能分析页面。

## 3. AI 知识点对应

| 知识点 | 项目实现 |
| --- | --- |
| 数据采集 | 摄像头采集视频帧，前端注册采集人脸样本 |
| 数据预处理 | 灰度化、缩放、直方图均衡化、人脸区域归一化 |
| 特征提取 | LBPH 局部二值模式直方图特征 |
| 模式识别 | LBPH 根据特征预测用户 label |
| 阈值判断 | confidence 小于等于阈值才判定为可信身份 |
| 监督学习 | 决策树根据考勤和成绩特征预测学生风险等级 |
| 可解释分析 | 输出风险分数、风险等级、摘要和教师建议 |

## 4. 系统流程

```text
注册人脸样本
-> 训练 LBPH 模型
-> 摄像头采集实时画面
-> 图像预处理
-> 人脸检测
-> 人脸识别与阈值判断
-> 签到决策
-> SQLite 保存结果和事件
-> 前端展示统计与 ASCII 画面
-> 决策树训练与学生风险预测
```

## 5. 演示顺序

1. 启动后端：`python -m app.main serve`。
2. 启动前端：进入 `frontend/` 后运行 `npm run dev`。
3. 在注册页面采集 3 张人脸样本并完成注册。
4. 进入实时签到页面，启动摄像头并展示 ASCII 画面。
5. 展示识别成功和重复签到拦截。
6. 进入数据中心查看签到记录和识别事件。
7. 进入系统分析查看出勤率、识别成功率和事件分布。
8. 进入智能分析页面，生成演示数据、训练模型并查看学生状态评估报告。

## 6. 关键答辩问题

1. 为什么选择 LBPH？

   LBPH 模型轻量、易部署，对小样本人脸识别演示友好，不需要 GPU，也适合本课程期末项目的本地运行要求。

2. 为什么每人采集 3 张样本？

   单张样本容易受角度和光照影响。采集 3 张样本可以覆盖轻微姿态变化，提高模型稳定性，同时仍保持注册流程简单。

3. 为什么区分签到记录和识别事件？

   签到记录只保存真正生效的业务结果，识别事件保存完整识别过程。这样既能避免重复签到污染业务表，也能分析识别质量和异常原因。

4. 智能分析为什么使用决策树？

   决策树训练速度快、依赖少、结果可解释，适合用出勤率、迟到次数、缺勤次数、重复签到次数、平均成绩和成绩变化等特征做小型风险分类演示。
