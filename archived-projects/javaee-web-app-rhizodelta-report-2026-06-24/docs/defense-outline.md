# 答辩提纲

本文档可用于制作 PPT 或组织口头汇报。建议 8 到 10 页，汇报控制在 6 到 8 分钟。

## 1. PPT 结构建议

### 第 1 页：项目标题

标题：RhizoDelta 图谱化非线性讨论系统后端实现

内容：

- 课程：《JavaEE企业级Web应用开发实战》
- 技术栈：Spring Boot、Neo4j、RabbitMQ、Redis、JWT、SSE
- 汇报人、班级、日期

### 第 2 页：项目背景

内容：

- 长讨论关系难理解。
- 结论来源难追踪。
- 后端需要支持异步 AI 编排和实时状态推送。

### 第 3 页：课程要求适配

内容：

- 课程方案偏单表 CRUD。
- 本项目是图谱讨论系统。
- Spring Boot、持久化、认证、缓存、消息队列、文件上传、测试部署均有对应实现。

### 第 4 页：总体架构

内容：

- Controller。
- Service。
- Repository / Neo4jClient。
- Redis。
- RabbitMQ。
- SSE。
- Actuator / Prometheus。

### 第 5 页：数据模型

内容：

- 图节点：用户发言、AI 共识、结果、话题、用户资料。
- 图关系：分支、合并、延续、综合、语义关联。
- 与 MyBatis-Plus 要求的对应关系。

### 第 6 页：认证授权

内容：

- Spring Security。
- JWT。
- BCrypt。
- Redis refresh token。
- access token 黑名单。
- 角色权限控制。

### 第 7 页：异步处理和实时推送

内容：

- 发帖投递 RabbitMQ。
- 消费者处理。
- 死信队列和重试。
- SSE 推送节点、边和决策事件。

### 第 8 页：文件、异常和部署

内容：

- MultipartFile 头像上传。
- 全局异常处理。
- 统一响应格式。
- Maven 构建和 Docker Compose 依赖服务。

### 第 9 页：难点与解决

内容：

- 图谱查询复杂。
- 发帖链路长。
- token 需要可撤销。
- 课程 CRUD 要求与真实图系统之间的对应说明。

### 第 10 页：总结与展望

内容：

- 完成了企业级 Web 后端能力展示。
- 后续可增强接口文档、测试覆盖、监控面板和部署脚本。

## 2. 口头汇报版提纲

1. 项目是什么。
2. 项目如何从 CRUD 能力扩展到图谱讨论场景。
3. 后端总体架构。
4. 图数据库如何建模。
5. 登录认证如何设计。
6. 发帖为什么使用消息队列。
7. SSE 如何实现实时更新。
8. 文件上传、异常处理和部署如何对应课程要求。
9. 总结收获和不足。

## 3. 3 分钟压缩版

1. 背景：RhizoDelta 用图谱表达长讨论的观点演化。
2. 后端能力：Spring Boot 接口、Neo4j 持久化、JWT 认证、Redis 状态、RabbitMQ 异步、SSE 实时事件。
3. 课程适配：以图数据库替代单表持久化形态，同时覆盖持久化、分页、事务、权限和部署。
4. 难点：图数据复杂、异步链路长、token 状态管理。
5. 总结：项目体现了企业级 Web 应用的分层、解耦和可靠性设计。
