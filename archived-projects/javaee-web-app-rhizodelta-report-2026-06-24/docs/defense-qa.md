# 答辩常见问答

## 1. 为什么课程方案是 MyBatis-Plus，但项目用了 Neo4j？

回答要点：

RhizoDelta 的核心数据是讨论节点和关系，涉及分支、合并、谱系和溯源，天然是图结构。Neo4j 和 Cypher 更适合表达这种关系。课程中的持久化、条件查询、分页、逻辑删除和事务要求，在项目中通过 Spring Data Neo4j、Neo4jClient、参数化 Cypher、`PagingParams` 和节点属性对应实现。

## 2. 这个项目如何体现 JavaEE 企业级 Web 能力？

回答要点：

项目覆盖 Spring Boot 工程、RESTful API、Service 分层、事务、统一响应、全局异常、Spring Security、JWT、Redis、RabbitMQ、文件上传、日志监控、Maven 构建和 Docker Compose 部署等能力。

## 3. 为什么发帖要使用 RabbitMQ？

回答要点：

发帖后可能需要落库、embedding、质量评估、AI 路由和图谱更新。如果同步完成会阻塞请求。RabbitMQ 可以让接口快速返回，后台异步处理，并支持重试、死信队列和发布确认。

## 4. SSE 的作用是什么？

回答要点：

SSE 用于把后端异步处理结果实时推送给前端，例如节点创建、边创建、决策完成、摘要生成和质量评分。相比轮询，SSE 延迟更低，也减少无效请求。

## 5. Redis 在项目中做什么？

回答要点：

Redis 主要保存 refresh token、access token 黑名单、在线状态和一些短期任务状态。它让 JWT 这种无状态访问令牌具备退出登录和撤销能力。

## 6. Spring Security 如何保护接口？

回答要点：

系统通过安全过滤器链处理 Bearer token。公开接口如登录、注册、健康检查放行，业务接口需要认证，治理类接口再根据 `USER`、`AGENT`、`ADMIN` 等角色控制权限。

## 7. 项目如何处理异常？

回答要点：

通过 `GlobalExceptionHandler` 统一捕获业务异常和系统异常，并转换为一致的 HTTP 响应结构。这样前端可以统一处理错误，后端日志也更容易定位问题。

## 8. 头像上传如何对应课程文件上传要求？

回答要点：

`AvatarController` 使用 `MultipartFile` 接收头像，服务层校验文件类型、大小和内容，再存储到 MinIO 或本地存储，并更新用户资料中的头像地址。

## 9. 图数据库中的节点和关系如何理解？

回答要点：

节点代表用户发言、AI 共识、结果、话题等实体；关系代表观点之间的延续、分叉、合并、综合和语义关联。相比关系型表，图数据库更适合直接查询谱系和溯源路径。

## 10. 项目如何保证异步链路可靠？

回答要点：

RabbitMQ 配置发布确认、消费重试和死信队列；后端处理结果通过 SSE 推送；关键操作在 Service 层设置事务边界。这样可以减少消息丢失、处理失败和状态不同步的问题。

## 11. 和传统 CRUD 管理系统相比，这个项目的优势是什么？

回答要点：

传统 CRUD 更适合单表或多表管理。RhizoDelta 处理的是复杂讨论关系，能展示节点演化、来源追踪和异步治理流程，业务复杂度更高，也更能体现企业级后端分层、解耦和可靠性设计。

## 12. 项目有什么不足？

回答要点：

不足包括业务模型复杂，首次理解成本较高；如果老师只按 MyBatis-Plus 检查，需要主动解释技术替代关系；后续还可以补充更多接口示例、测试覆盖、部署截图和监控面板。

## 13. 如果老师要求展示源码，应看哪些部分？

回答要点：

可以重点展示：

- 启动类和配置文件。
- `AuthController` 与安全配置。
- `PostController` 和消息投递。
- 图节点 Repository 或 Neo4jClient 查询。
- RabbitMQ 配置和消费者。
- SSE 服务。
- 全局异常处理。
- 头像上传服务。
