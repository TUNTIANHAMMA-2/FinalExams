# 项目理解速览

## 1. 一句话介绍

RhizoDelta 是一个图谱化非线性讨论系统。JavaEE 课程报告重点说明它的 Spring Boot 后端如何支撑用户认证、发帖、图谱查询、异步处理、实时推送和工程化部署。

## 2. 要解决的问题

传统论坛或评论区通常按时间顺序排列内容，长讨论中容易出现：

- 观点关系不清。
- 结论来源难追踪。
- 相似观点、反驳观点和补充证据混在一起。
- 后台处理 AI 编排时链路较长，前端需要及时知道状态变化。

RhizoDelta 通过图数据库保存节点和关系，用异步消息队列处理高成本任务，并通过 SSE 把结果实时推送给前端。

## 3. 项目定位

本课程设计关注企业级 Web 后端能力。正式报告中的项目依据是：

- 后端框架：Spring Boot 3。
- 数据层：Spring Data Neo4j、Neo4jClient、Cypher。
- 认证授权：Spring Security、JWT、BCrypt、Redis token 状态。
- 消息队列：RabbitMQ。
- 实时通信：Server-Sent Events。
- 文件能力：头像上传和存储。
- 可观测性：日志、Actuator、Prometheus 指标。

课程方案中要求的 MyBatis-Plus CRUD 能力，在本项目中由图数据库实体、Repository、参数化 Cypher、分页查询、逻辑删除和事务边界对应实现。

## 4. 用户角色与使用路径

主要角色：

| 角色 | 说明 |
| --- | --- |
| 普通用户 | 注册登录、发布话题、回复节点、浏览图谱 |
| 治理用户 / Agent | 执行分支、合并、注入、物化、复核等治理动作 |
| 管理员 | 管理用户、权限、审计和异常处理 |

典型后端链路：

1. 用户登录获取 JWT。
2. 前端携带 token 提交发帖请求。
3. 后端校验权限并把帖子事件投递到 RabbitMQ。
4. 消费者异步落库、生成 embedding、执行 AI 路由或质量评估。
5. Neo4j 保存节点、边和溯源关系。
6. SSE 服务把节点创建、边创建、决策完成等事件推送给前端。

## 5. 核心模块

| 模块 | 作用 |
| --- | --- |
| Auth | 注册、登录、刷新 token、退出登录 |
| Security | JWT 过滤器、权限控制、密码加密 |
| Graph Query | 根话题、节点详情、谱系、后代、溯源查询 |
| Post Processing | 接收发帖请求并投递异步任务 |
| Decision / Review | 分支、合并、复核、回滚等治理操作 |
| RabbitMQ | 发帖异步处理、死信队列、重试和发布确认 |
| Redis | token 黑名单、refresh token、在线状态和短期任务状态 |
| SSE | 实时推送节点、边、决策和质量评分事件 |
| Avatar | 头像上传、校验、存储和访问 |

## 6. 答辩重点表达

答辩时要说明：项目从课程方案中的信息管理系统能力出发，扩展到图谱讨论场景，覆盖了 Spring Boot、RESTful API、认证授权、数据持久化、事务、消息队列、缓存、文件上传、异常处理、测试和部署等企业级 Web 核心能力。
