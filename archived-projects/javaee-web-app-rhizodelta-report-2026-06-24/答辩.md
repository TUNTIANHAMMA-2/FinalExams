# JavaEE 企业级 Web 应用开发实战答辩

## 1. 项目简介

本课程设计基于 RhizoDelta 图谱化非线性讨论系统整理，重点说明 Spring Boot 后端、认证授权、图数据库、消息队列、缓存、文件上传、实时通信和部署能力。项目以课程常见的 CRUD 能力为基础，进一步扩展到“观点节点、关系边、共识演化”的企业级 Web 应用场景。

## 2. 已完成的核心功能

- 用户注册、登录、JWT 鉴权和 refresh token 管理。
- 用户发帖、回复、话题查询、节点详情、谱系和后代查询。
- 基于 Neo4j 的图节点、图关系和索引设计。
- RabbitMQ 异步处理发帖链路，并通过 SSE 推送增量事件。
- Redis 保存 token 状态、在线状态和部分短期业务状态。
- 头像上传、用户资料、关注和屏蔽能力。
- 全局异常处理、统一响应封装、日志和监控指标。

| 课程要求 | 项目实现 |

## 4. 技术亮点

- 使用 Neo4j 表达非线性讨论中的分支、合并、延续和关联关系。
- 使用 RabbitMQ 解耦高成本的 AI 编排和帖子处理流程。
- 使用 SSE 将后端异步处理结果实时推送给前端。
- 使用 Spring Security + JWT + Redis 实现无状态访问令牌和可撤销会话。
- 使用统一响应、全局异常和服务分层保证接口风格一致。

## 5. 演示顺序

1. 展示登录注册和 token 鉴权。
2. 展示创建话题或回复节点后返回排队状态。
3. 展示后台异步处理完成后，图谱节点和边通过 SSE 更新。
4. 展示节点详情、谱系 lineage、后代 children 和溯源 provenance。
5. 展示头像上传、用户资料、关注/屏蔽等基础 Web 应用能力。
6. 展示监控、日志和 Docker/Maven 部署方式。

## 6. 常见问题准备

1. 为什么没有使用 MyBatis-Plus？

   项目核心数据是图节点和关系，谱系查询、分支合并和语义关联更适合用 Neo4j 与 Cypher 表达；报告中已把 MyBatis-Plus 的课程要求映射到 Spring Data Neo4j 和 Neo4jClient 的替代实现。

2. 为什么需要 RabbitMQ？

   发帖后需要执行落库、embedding、质量评估和 AI 路由等耗时任务。使用消息队列可以让接口快速返回，同时保证后台任务可重试、可解耦、可观测。

3. Redis 的作用是什么？

   Redis 主要用于 refresh token、access token 黑名单、在线状态和短期任务状态。这样可以让无状态 JWT 具备退出登录、撤销 token 和会话状态管理能力。

4. 项目如何体现企业级 Web？

   项目覆盖认证授权、异步消息、图数据库、文件上传、统一异常、事务、日志监控、部署和前后端分离，体现了企业级 Web 应用中分层、解耦和可靠性设计。

## 7. 总结

本项目完成了一个较完整的企业级 Web 应用后端设计与实现说明。答辩时重点强调：业务形态从信息管理扩展到图谱讨论，但课程要求中的 Spring Boot、持久化、认证授权、接口设计、消息队列、文件处理、测试和部署能力都已经在真实工程中落地。
