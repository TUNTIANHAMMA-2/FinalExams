# 物流管理系统答辩提纲

## 1. 项目介绍

本项目是一个基于 Spring Boot 的物流管理系统，主要解决物流企业对客户、司机、车辆和运单的基础管理需求。项目重点不是做复杂业务，而是完整展示 JavaEE 课程要求中的项目配置、数据库设计、持久层开发、Web 层开发和 RESTful 接口设计。

## 2. 技术选型

- Spring Boot：快速搭建 Web 项目。
- Spring MVC：处理页面请求和 REST 接口请求。
- Thymeleaf：渲染后台管理页面。
- MyBatis-Plus：简化 CRUD 开发。
- MySQL：保存物流业务数据。
- Lombok：减少实体类 getter/setter 等模板代码。
- Validation：完成表单和接口参数校验。

## 3. 数据库设计

系统设计了四张表：客户表、司机表、车辆表、运单表。运单表是核心表，通过外键关联客户、司机和车辆，能够完整表达“某客户的某批货物由某司机驾驶某车辆从起点运到终点”的业务流程。

## 4. 功能演示顺序

1. 打开首页，展示统计数据。
2. 打开基础资料页，展示客户、司机、车辆数据。
3. 打开运单管理页，按状态或关键字查询。
4. 新增一条运单，说明表单校验和默认状态。
5. 编辑运单，将状态改为运输中或已送达。
6. 删除运单，说明 MyBatis-Plus 逻辑删除。
7. 使用 curl 或接口工具访问 `/api/shipments`，展示统一响应结构。

## 5. 核心代码讲解

- `application-dev.yml`：端口、数据源、Thymeleaf 缓存、MyBatis-Plus SQL 日志配置。
- `ApiResponse`：统一返回 `code/message/data`。
- `ShipmentRestController`：展示 `@RequestParam`、`@PathVariable`、`@RequestBody`。
- `ShipmentServiceImpl`：展示 `@Transactional` 和业务校验。
- `ShipmentMapper`：展示 MyBatis-Plus 基础 CRUD 和自定义关联查询。

## 6. 可回答的问题

**问：为什么使用 MyBatis-Plus？**

答：MyBatis-Plus 能直接提供基础 CRUD，减少重复 SQL，同时保留 MyBatis 灵活写 SQL 的能力。本项目用 BaseMapper 完成基础增删改查，用自定义查询完成运单关联展示。

**问：事务控制在哪里体现？**

答：运单新增、修改、删除会改变数据库核心业务数据，因此在 `ShipmentServiceImpl` 对应方法上添加 `@Transactional(rollbackFor = Exception.class)`，异常时自动回滚。

**问：统一响应有什么作用？**

答：统一响应让前端或接口调用方总是拿到固定结构，包含状态码、提示信息和业务数据，便于处理成功和失败结果。

**问：为什么没有做 Redis 和 RabbitMQ？**

答：本项目目标是期末课程设计提交和答辩，重点展示 Spring MVC、MyBatis-Plus、MySQL、RESTful 接口和事务控制。缓存和消息队列属于扩展能力，当前版本先保证核心业务完整、清晰、可运行。
