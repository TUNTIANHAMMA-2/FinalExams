# RhizoDelta 前端课程设计答辩速用稿

## 1. 项目简介

本项目是 RhizoDelta 图谱化非线性讨论系统的前端实现。它解决的是长讨论中观点关系不清、结论来源难追踪、新用户理解成本高的问题。系统把讨论内容组织成节点和边：节点表示用户发言、AI 共识、阶段性结果或摘要，边表示延续、分叉、合并和关联关系。

课程名称是《Vue.js应用开发》，但本交付物基于真实工程源码整理，实际技术栈为 React、TypeScript、Vite、React Router、Zustand、React Flow 和 SSE。答辩时应主动说明：本次重点展示的是前端应用开发能力，而不是把真实 React 工程硬写成 Vue 工程。

## 2. 已完成的核心功能

- 登录注册与路由鉴权。
- 首页根话题和动态入口。
- 桌面端图谱工作区。
- 移动端讨论树。
- 节点详情、溯源、关联和审计信息展示。
- 发布新话题和回复节点。
- SSE 实时接收节点创建、关系创建、决策完成、摘要生成和质量评分事件。
- 命令面板检索和个人设置。

## 3. 技术与设计重点

- `src/App.tsx`：使用 React Router 划分公开路由和受保护路由。
- `src/api/client.ts`：统一封装请求、token、401 处理和 `{ code, message, data }` 响应解析。
- `src/stores/*.ts`：使用 Zustand 按职责管理认证、图谱、SSE、首页、移动端讨论树和 UI 状态。
- `src/components/GraphWorkspace.tsx`：根据视口选择桌面图谱或移动端讨论树。
- `src/hooks/useSse.ts`：通过 `/api/events/stream` 接收后端事件并局部刷新状态。

## 4. 演示顺序

1. 登录页：说明路由鉴权和会话状态。
2. 首页：展示根话题和动态入口。
3. 工作区：展示左侧话题、中间图谱、右侧详情面板。
4. 节点详情：说明正文、作者、质量评分、溯源、关联和审计。
5. 发布回复：说明异步提交和排队反馈。
6. 实时更新：说明 SSE 事件驱动刷新。
7. 移动端视图：说明为什么小屏使用讨论树而不是复杂图谱。

## 5. 主要难点与解决方法

| 难点 | 解决方法 |
|---|---|
| 图谱节点、边、关联、审计数据复杂 | API 层和 store 层统一管理，组件只负责展示和交互 |
| 发帖后存在后端异步编排 | 前端先给排队反馈，再通过 SSE 接收最终事件 |
| 桌面和移动端交互差异大 | 桌面使用图谱画布，移动端使用嵌套讨论树 |
| 登录状态和错误处理容易重复 | 路由层集中鉴权，API 层集中处理请求错误 |

## 6. 总结

本项目完成了一个较完整的前端系统，覆盖组件化、路由、状态管理、接口封装、实时通信、响应式设计和文档整理。项目不足是业务复杂度较高，报告中还可以继续补充更多真实运行截图和接口说明；后续可继续完善图谱筛选、讨论路径回放、移动端弱网提示和自动化测试。
