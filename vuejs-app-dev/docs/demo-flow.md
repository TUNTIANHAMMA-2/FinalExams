# 演示流程脚本

本文档用于答辩现场演示。建议演示时间控制在 4 到 6 分钟，重点展示完整业务链路，不要停留在单个页面样式。

## 1. 演示前准备

确认内容：

- 后端服务已启动，并能访问 `/api/**`。
- 前端 Vite 服务已启动。
- 浏览器中准备一个普通用户账号。
- 数据库中至少有一个根话题和若干讨论节点。
- 如果现场网络或后端不稳定，准备报告中的截图作为备用说明。

推荐打开的材料：

- 正式报告：`../Vue.js应用开发期末课程设计报告.docx`
- 项目理解速览：`./project-understanding.md`
- 系统设计说明：`./system-design.md`

## 2. 开场介绍

建议用 30 秒说明：

“本项目是 RhizoDelta 图谱化非线性讨论系统的前端实现。它解决的是长讨论中观点关系不清、结论来源难追踪的问题。前端把讨论内容展示为节点和边，同时提供移动端讨论树、节点详情、发布回复和实时更新。”

需要主动说明：

“课程名称是 Vue.js 应用开发，但本次交付基于真实工程源码，实际采用 React、TypeScript 和 Vite。这里重点展示的是前端应用开发能力，包括组件化、路由、状态管理、接口封装和响应式设计。”

## 3. 演示步骤

### 步骤一：登录与路由鉴权

展示页面：`/login`

讲解点：

- 未登录用户只能进入登录页。
- 登录后 token 保存到状态和本地存储。
- 业务页面通过路由守卫统一保护。

可说的话：

“这里不是在每个页面里重复判断登录状态，而是在路由层用 RequireAuth 统一控制。这样页面本身可以更专注业务逻辑。”

### 步骤二：首页入口

展示页面：`/`

讲解点：

- 首页展示根话题、动态和辅助入口。
- 用户先选择讨论主题，再进入工作区。
- 首页降低了直接面对复杂图谱的理解成本。

可说的话：

“首页相当于系统的信息入口，用户不需要一进来就看复杂图谱，而是先从根话题和动态理解当前系统中有哪些讨论。”

### 步骤三：桌面图谱工作区

展示页面：`/workspace/:rhizomeId`

讲解点：

- 左侧是话题列表。
- 中间是图谱画布。
- 右侧是节点详情面板。
- 画布可切换“版本视图”和“探索视图”。

可说的话：

“这里的节点表示用户观点、共识或阶段性结果，边表示观点之间的继承、分叉或关联。相比传统评论列表，图谱更容易看出讨论是如何演化的。”

### 步骤四：节点详情与治理信息

操作：点击一个节点，打开右侧详情面板。

讲解点：

- 展示节点正文、作者、创建时间。
- 展示质量评分、AI 决策说明、编排状态。
- 通过标签页组织详情、溯源、关联、审计。

可说的话：

“节点不是单纯的图形元素，它背后有正文、作者、来源、关联和审计记录。这样可以解释一个结论从哪里来，也可以追踪它经过了哪些处理。”

### 步骤五：发布或回复

操作：选择节点后发布回复，或从入口发布新话题。

讲解点：

- 前端校验空内容和登录状态。
- 提交后后端异步处理。
- 前端先给出排队反馈，不阻塞用户。
- 后续结果由 SSE 推送回来。

可说的话：

“发帖后前端不会一直等待后端完成 AI 决策，而是提交请求后进入异步流程。后端完成节点创建、边创建或质量评分后，通过 SSE 推送事件给前端。”

### 步骤六：实时更新

操作：观察新节点、新边、状态或通知刷新。

讲解点：

- SSE 监听 `/api/events/stream`。
- 事件包括节点创建、关系创建、决策完成、摘要生成、质量评分等。
- 前端根据事件局部刷新，不必整页刷新。

可说的话：

“这里体现的是事件驱动的数据更新。前端不是靠用户手动刷新，而是持续接收后端事件，让图谱和讨论树尽量保持最新。”

### 步骤七：移动端讨论树

操作：切换移动端视口或展示移动端截图。

讲解点：

- 小屏不强行展示复杂图谱。
- 移动端使用嵌套评论树。
- 支持回复、长按菜单和可见时刷新。

可说的话：

“响应式设计不只是把宽度变窄。这个项目在移动端换成更适合阅读的讨论树，保留核心讨论关系，同时减少小屏操作负担。”

## 4. 收尾总结

建议用 30 秒总结：

“本项目完成了登录鉴权、首页、图谱工作区、节点详情、发布回复、实时更新、移动端适配和设置页等功能。技术上主要实践了组件化开发、React Router 路由、Zustand 状态管理、统一 API 封装、SSE 实时通信和响应式界面设计。项目不足是业务复杂度较高，后续可以继续补充运行截图、接口文档和更多测试。”
