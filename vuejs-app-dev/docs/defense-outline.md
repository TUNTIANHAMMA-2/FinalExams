# 答辩提纲

本文档可用于制作 PPT 或组织口头汇报。建议 8 到 10 页 PPT，汇报控制在 6 到 8 分钟。

## 1. PPT 结构建议

### 第 1 页：项目标题

标题：RhizoDelta 图谱化非线性讨论系统前端实现

内容：

- 课程：《Vue.js应用开发》期末课程设计
- 说明：真实工程采用 React + TypeScript + Vite
- 汇报人、班级、日期

讲解重点：

“本项目关注前端应用开发能力，围绕一个图谱化讨论系统完成页面、状态、接口、实时更新和移动端适配。”

### 第 2 页：项目背景与问题

内容：

- 长讨论中观点关系不清。
- 结论来源难追踪。
- 新用户阅读成本高。
- 普通评论列表无法表达分叉、合并和演化关系。

讲解重点：

“项目不是再做一个普通论坛，而是尝试把讨论过程结构化。”

### 第 3 页：项目目标

内容：

- 用户登录和会话保持。
- 首页话题入口。
- 图谱化工作区。
- 节点详情、溯源、关联、审计。
- 发布新话题和回复。
- SSE 实时更新。
- 移动端讨论树。

讲解重点：

“目标是做出一个较完整的前端系统，而不是单个静态页面。”

### 第 4 页：总体架构

推荐配图：

- `../images/01_fullstack_architecture.png`
- `../images/03_frontend_architecture.png`

内容：

- React 页面组件。
- React Router 路由。
- Zustand store。
- API client。
- 后端 REST 与 SSE。
- React Flow 图谱画布。

讲解重点：

“组件不直接处理所有数据细节，复杂状态交给 store，接口细节交给 API 层。”

### 第 5 页：核心页面设计

内容：

- 登录页。
- 首页。
- 桌面图谱工作区。
- 节点详情面板。
- 移动端讨论树。
- 设置页。

讲解重点：

“页面不是孤立存在的，它们组成了从登录、找话题、看图谱、看详情、发帖到实时刷新的完整路径。”

### 第 6 页：数据流与状态管理

内容：

- 登录数据流。
- 工作区加载数据流。
- 发帖异步数据流。
- SSE 实时更新数据流。

推荐图示：

组件 -> Store -> API -> 后端 -> SSE -> Store -> 组件

讲解重点：

“这个项目中最重要的不是某一个组件，而是前端如何管理跨页面、跨组件和异步事件的数据流。”

### 第 7 页：关键实现与难点

内容：

- 路由鉴权集中处理。
- API 统一封装请求和错误。
- 图谱状态由 store 管理。
- 桌面和移动端使用不同交互。
- SSE 事件局部刷新。

讲解重点：

“难点来自业务链路长、状态复杂和设备差异大。解决方式是分层、拆模块和事件驱动。”

### 第 8 页：运行效果展示

内容：

- 登录后首页。
- 图谱工作区。
- 节点详情。
- 发布回复。
- 移动端讨论树。

讲解重点：

“展示时按用户路径走，不要只展示截图。先进入系统，再进入话题，再查看节点，再发布回复。”

### 第 9 页：测试与质量保障

内容：

- 使用 TypeScript 做类型约束。
- 使用 ESLint 做代码检查。
- 使用 Vitest 和 Testing Library 做单元测试。
- 源码中已有 store、组件、图谱布局、移动端交互等测试文件。

讲解重点：

“质量保障不是只靠手工点页面，而是通过类型、代码检查和测试共同降低风险。”

### 第 10 页：总结与展望

内容：

- 完成了较完整前端系统。
- 掌握了组件化、路由、状态、接口、实时通信、响应式等能力。
- 不足：截图和接口文档还可继续补充，真实运行演示依赖后端服务。
- 展望：增加更多图谱筛选、路径回放、移动端弱网处理和测试覆盖。

讲解重点：

“本次课程设计让我把前端知识放到真实业务链路中理解。”

## 2. 口头汇报版提纲

可以按下面顺序讲：

1. 我做的项目是什么。
2. 它解决什么问题。
3. 系统有哪些主要功能。
4. 前端技术栈和总体架构。
5. 重点模块如何设计。
6. 最难的地方和解决方法。
7. 演示系统运行效果。
8. 总结收获和不足。

## 3. 3 分钟压缩版

如果答辩时间很短，可以只讲：

1. 背景：长讨论关系混乱，项目用图谱表达讨论演化。
2. 功能：登录、首页、图谱工作区、节点详情、发布回复、实时更新、移动端讨论树。
3. 技术：React、TypeScript、Vite、React Router、Zustand、React Flow、SSE。
4. 设计：路由管页面，store 管状态，API 层管请求，SSE 管实时刷新。
5. 难点：复杂图谱、异步事件和移动端适配。
6. 总结：完成了一个完整前端系统，体现课程中的前端应用开发能力。

## 4. 答辩中容易被问到的点

- 为什么课程叫 Vue.js，项目却是 React？
- 图谱相比普通评论列表有什么价值？
- 前端如何保证登录状态？
- 发帖后为什么不是马上出现最终节点？
- SSE 和普通轮询相比有什么优点？
- 移动端为什么不用图谱画布？
- Zustand 在项目中解决了什么问题？
- 后端不可用时前端如何处理错误？
- 项目有哪些不足和后续改进方向？
