# 答辩常见问答

## 1. 为什么课程是 Vue.js，项目却使用 React？

回答要点：

课程目录和报告标题保留 Vue.js 是课程要求。项目真实落地时使用的是 React、TypeScript 和 Vite。答辩时我重点展示的是前端应用开发能力，包括组件化、路由管理、状态管理、接口封装、响应式设计和工程化流程。这些能力在 Vue 和 React 中是相通的，因此报告以真实源码为依据展开，而不是把 React 项目硬改成 Vue 表述。

## 2. 这个项目和普通论坛或评论区有什么区别？

回答要点：

普通评论区通常按时间线排列，长讨论中很难看清观点之间的继承、分叉、反驳和合并关系。RhizoDelta 用节点和边表达讨论结构，节点可以是用户发言、AI 共识或阶段性结果，边表示观点之间的关系。这样更容易追踪结论来源，也方便新用户理解讨论脉络。

## 3. 前端主要完成了哪些功能？

回答要点：

前端完成了登录注册、路由鉴权、首页话题入口、桌面图谱工作区、移动端讨论树、节点详情面板、发布与回复、实时事件更新、命令面板检索、个人设置等功能。整体形成了从登录到进入话题、查看图谱、发布内容、接收实时更新的完整业务流程。

## 4. 为什么要把 API 请求统一封装？

回答要点：

统一封装可以避免每个组件重复处理 token、请求头、错误解析和后端响应结构。项目中的 `src/api/client.ts` 会自动附加 Bearer token，处理 401 登录失效，解析 `{ code, message, data }` 结构，并把异常统一抛出。这样组件更专注交互和展示，接口细节集中维护。

## 5. Zustand 在项目中解决了什么问题？

回答要点：

项目有很多跨组件状态，例如登录状态、图谱节点和边、当前选中节点、右侧面板、SSE 连接状态、移动端讨论树和通知。如果全部放在组件局部 state 中，会出现层层传参和状态不一致。Zustand 让这些状态按业务职责拆分到不同 store 中，组件可以直接订阅自己需要的数据。

## 6. 发帖后为什么不是马上返回最终结果？

回答要点：

发帖后后端可能要执行异步编排、AI 决策、节点创建、关系创建、摘要生成或质量评分。如果前端一直等待最终结果，会影响交互体验。因此前端提交后先显示“已排队”反馈，后端完成后通过 SSE 推送事件，前端再局部更新节点和边。

## 7. SSE 的作用是什么？为什么不用普通轮询？

回答要点：

SSE 用于后端主动推送事件，例如 `NODE_CREATED`、`EDGE_CREATED`、`DECISION_COMPLETE`、`SUMMARY_GENERATED` 和 `QUALITY_SCORED`。相比轮询，SSE 不需要前端频繁请求后端，延迟更低，也更适合这种由后端异步流程驱动的状态变化。

## 8. 移动端为什么不用和桌面端一样的图谱画布？

回答要点：

复杂图谱需要较大的屏幕空间，手机上缩放、拖拽和阅读节点都会比较困难。本项目在移动端切换为嵌套讨论树，保留讨论层级和回复关系，同时更适合阅读和输入。这个设计说明响应式不只是样式缩放，而是按设备场景选择更合适的信息结构。

## 9. 图谱工作区有哪些关键组成？

回答要点：

桌面端工作区由左侧话题列表、中间图谱画布和右侧详情面板组成。中间画布有谱系视图和探索视图，右侧面板展示节点正文、作者、质量评分、溯源、关联和审计等信息。用户可以通过选择节点理解观点关系和节点来源。

## 10. 如何处理登录失效？

回答要点：

路由层通过 `RequireAuth` 检查 token，没有 token 时跳转到登录页。API 客户端在请求返回 401 时会清除 token，后续页面会回到未登录状态。这样认证控制集中在路由和 API 两个边界位置。

## 11. 项目的主要难点是什么？

回答要点：

主要难点有三个。第一，图谱数据复杂，节点、边、关联、审计和质量状态来自不同接口。第二，发帖和 AI 编排是异步流程，需要用事件驱动更新前端。第三，桌面端和移动端交互差异大，需要设计两套不同的信息呈现方式。项目通过 API 分层、Zustand store、SSE 和移动端讨论树解决这些问题。

## 12. 项目有什么不足？

回答要点：

不足主要包括：业务场景较复杂，首次使用需要一定学习成本；正式报告还可以继续补充更多真实运行截图；接口文档可以更细；部分异常场景和权限边界的测试还可以继续加强。后续可以增加图谱筛选、路径回放、移动端弱网提示和更完整的自动化测试。

## 13. 如果老师要求展示源码，你会看哪些文件？

回答要点：

可以重点展示这些文件：

- `src/components/panels/NodeDetailPanel.tsx`：节点详情。

## 14. 这个项目体现了哪些课程能力？

回答要点：

它体现了完整前端应用开发能力，包括组件拆分、页面路由、登录鉴权、接口请求、状态管理、响应式设计、表单处理、实时通信、错误处理、测试和项目文档整理。虽然技术栈不是 Vue，但这些能力对应的是前端课程中的核心训练目标。

## 15. 后续如果改成 Vue，需要怎么迁移？

回答要点：

可以保留业务分层思想和接口设计，把 React 组件迁移为 Vue 单文件组件，把 React Router 换成 Vue Router，把 Zustand store 换成 Pinia，把 Hooks 逻辑改成 Vue composables。API 层、数据模型、业务流程、SSE 事件类型和页面结构都可以复用设计思路。
