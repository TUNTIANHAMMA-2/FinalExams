> 骨架；填好交付物后再据此整理 3–5 分钟口头稿。

## 1. 开场（选题与定位）

- 我测试的是自己的项目 RhizoDelta：一个图谱化非线性讨论系统，B/S 架构，Spring Boot + Neo4j 后端、React/Vite 前端。
- 选它做被测系统的原因：真实可运行、接口丰富、对业务最熟悉，能写出有依据的用例。

## 2. 测试范围与策略

- 本轮核心子集：认证授权、用户资料基础接口、图谱查询基础接口、登出与 token 吊销；发帖与关联、头像上传、关注/拉黑、治理决策与复核列为后续扩展。
- 测试类型：黑盒功能测试为主 + 接口测试专项（Postman）；SSE/异步/AI 仅做连通性冒烟。
- 用例设计方法：等价类、边界值、错误推测、因果图、场景法；测试用例表中已单独补充输入条件分析工作表。

## 3. 工作量与产出

- 功能/接口用例 28 条：20 条已实测，执行率 100%；8 条为后续回归补充设计；验收版断言 58 条，通过 58。
- 发现缺陷 2 个（均低危）：BUG-001 重复注册应 409 实返 400；BUG-002 时间字段格式不一致。
- Postman 自动化用例 20 条，覆盖认证/用户资料/图谱查询/认证收尾；用 newman 导出 HTML 测试报告（`generated/postman-report.html`）。
