# 测试策略与用例设计

## 1. 测试目标

1. 确认 RhizoDelta 核心功能可用、业务流程正常。
2. 确认接口的入参校验、鉴权约束与错误处理符合预期。
3. 发现并记录缺陷，给出系统质量结论与上线建议。

## 2. 测试类型

| 类型 | 说明 | 本次 |
| --- | --- | --- |
| 黑盒功能测试 | 以用户/接口视角验证输入→输出对应关系 | 主体 |
| 接口测试 | Postman 对 `/api/**` 直接发请求并断言 | 专项 |
| 软件审查 | 评审需求/用例 | 辅助 |
| 性能 / UI 自动化 | JMeter / Selenium | 三选一中**未选**，不展开 |

## 3. 用例设计方法（对应总结报告 4.1）

- **等价类划分**：合法/非法用户名、密码长度合法区间内外等。
- **边界值分析**：用户名/密码/显示名长度的"刚好等于、刚大于、刚小于"。
- **错误推测**：缺字段、空值、超长、特殊字符、重复注册、越权访问他人资源。
- **场景法**：注册→登录→发帖→查询图谱→登出 的完整业务链。
- **因果图**：登录的"用户名/密码/账号状态"组合与结果。

## 4. 工具选型（接口测试专项）

- 选 **Postman**：直接对运行中的后端 `http://localhost:8090` 发请求；用环境变量管理 `baseUrl` 与登录后的 `token`；用 Tests 脚本断言状态码、`ApiResponse` 结构和业务字段；最终导出 Collection Runner / Newman 测试报告。
- 详见 [../deliverables/4-接口测试-Postman.md](../deliverables/4-接口测试-Postman.md)。

沿用模板：严重 / 很高 / 高 / 中 / 低，详见 [../deliverables/3-Bug缺陷报告清单.md](../deliverables/3-Bug缺陷报告清单.md)。

- 核心模块用例执行率 100%，无"严重/很高"级未关闭缺陷；接口用例断言全部通过或缺陷已记录并定级。
