# 项目理解速览（被测系统：RhizoDelta）

## 1. 一句话介绍

RhizoDelta 是一个**图谱化非线性讨论系统**：用图数据库保存讨论节点与关系，用异步队列处理高成本任务，并通过 SSE 把处理结果实时推送给前端。本次作为软件测试的被测系统（SUT）。

## 2. 技术栈与架构

- 架构：B/S 全栈。
- 后端：Spring Boot 3、Spring Data Neo4j（Cypher）、Spring Security + JWT + BCrypt、Redis（token 状态）、RabbitMQ（异步）、SSE（实时）。
- 前端：React + Vite。
- 运行：后端默认端口 **8090**（本地实例运行中：`http://localhost:8090`）。

## 3. 角色

| 角色 | 说明 |
| --- | --- |
| 普通用户 | 注册登录、发帖、回复节点、浏览图谱、关注/拉黑 |
| 治理用户 / Agent | 分支、合并、注入、物化、复核、回滚等治理动作 |
| 管理员 | 用户、权限、审计与异常处理 |

## 4. 功能模块与测试范围

| 编号 | 模块 | 主要功能 | 本次范围 |
| --- | --- | --- | --- |
| RD-ST-SRS001 | 认证授权 | 注册、登录、刷新令牌、登出、当前用户、JWT 鉴权 | 核心 |
| RD-ST-SRS002 | 用户资料与社交 | 个人资料查看/修改、头像上传/删除、关注、拉黑、动态流、在线状态 | 核心 |
| RD-ST-SRS003 | 发帖与关联 | 发布帖子（异步入队）、创建/删除节点关联 | 核心 |
| RD-ST-SRS004 | 图谱查询 | 根话题、节点详情、拓扑上下文、谱系、子代、讨论树、溯源、关联 | 核心 |
| RD-ST-SRS005 | 治理决策与复核 | 合并/分支/注入/物化/fork/交叉综合/join、回滚、待审/审批/驳回、审计 | 选测 |
| RD-ST-SRS006 | AI 与实时 | 节点摘要、向量获取/写入/相似检索、SSE 事件流 | 仅冒烟/范围外 |

## 5. 测试范围边界（重要）

- **纳入**：上述核心模块的同步 REST 行为、鉴权约束、参数校验、错误处理（`GlobalExceptionHandler` 统一响应）。
- **冒烟为主**：SSE `/api/events/stream` 仅验证可建立连接、收到事件；发帖异步落库验证"最终一致"而非即时返回。
- **范围外**：AI 编排质量、向量召回准确率、RabbitMQ 死信重试细节——课程作业不展开，必要时在总结报告说明取舍理由。

## 6. 与参考模板的对应关系

参考模板样例系统是"B/S 资产管理系统"（权限/登录/个人信息/存放地点/供应商/资产）。映射到 RhizoDelta：权限+登录 → 认证授权；个人信息 → 用户资料与社交；资产/存放地点/供应商等 CRUD → 发帖与关联 + 图谱查询；并新增治理决策模块体现系统特色。
