# 项目理解速览

## 1. 一句话介绍

宿舍报修管理系统是面向高校宿舍维修场景的管理信息系统，用于规范学生报修、管理员审核派工、维修员处理反馈和后勤统计分析的完整流程。

## 2. 要解决的问题

传统宿舍报修通常依赖电话、微信群或线下登记，容易出现以下问题：

- 报修信息分散，后勤人员难以及时汇总。
- 维修进度不透明，学生无法确认处理状态。
- 派工记录和维修反馈难以追踪。
- 后勤统计依赖人工整理，效率低且容易遗漏。

本系统把报修流程抽象为可管理的工单生命周期，让各类角色在同一流程中协同。

## 3. 项目定位

本作业是《软件工程导论》的完整设计报告，重点展示：

- 如何识别参与者、业务对象和系统边界。
- 如何使用 DFD、UML 类图、状态图等表达系统分析结果。
- 如何把需求分析转换为总体功能结构。
- 如何对关键模块进行详细设计、PDL 伪代码和测试设计。

## 4. 用户角色与业务路径

主要参与者：

| 角色 | 主要职责 |
| --- | --- |
| 学生 | 提交报修、查看进度、确认维修结果、评价服务 |
| 管理员 | 审核报修、派工、跟踪工单状态、处理异常 |
| 维修员 | 接收任务、维修处理、填写反馈 |
| 后勤管理部门 | 查询统计、分析维修效率和问题类型 |

典型路径：

1. 学生填写宿舍、故障类型、故障描述和附件。
2. 系统校验宿舍信息和报修内容。
3. 管理员审核并派给维修员。
4. 维修员处理后填写维修结果。
5. 学生确认并评价。
6. 后勤按时间、宿舍、故障类型统计分析。

## 5. 核心设计成果

| 成果 | 作用 |
| --- | --- |
| UML 类图 | 描述学生、宿舍、工单、派工、维修员、管理员等静态关系 |
| 顶层 DFD / 0 层 DFD | 描述外部实体、处理过程、数据流和数据存储 |
| 工单状态图 | 描述从提交、审核、派工、维修到确认关闭的生命周期 |
| 系统结构图 | 把 DFD 中的加工转换为功能模块层次 |
| 程序流程图 / N-S 图 | 展示关键模块内部逻辑 |
| PDL 伪代码 | 用接近程序语言的方式描述报修受理模块 |
| 白盒/黑盒测试 | 验证核心模块的路径、条件、边界和等价类 |

## 6. 答辩重点表达

可以按“为什么选题、流程是什么、用了哪些软件工程方法、设计如何保持一致、测试如何覆盖关键逻辑”展开。重点是证明每个图表、伪代码和测试用例都围绕同一条报修主线。
