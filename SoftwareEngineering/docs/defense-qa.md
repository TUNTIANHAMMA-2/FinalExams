# 答辩常见问答

## 1. 为什么选择宿舍报修管理系统？

回答要点：

宿舍报修是高校中常见的事务管理场景，角色明确、流程清晰、数据对象稳定，适合展示软件工程导论中的需求分析、总体设计、详细设计和测试设计方法。

## 2. 系统的核心对象是什么？

回答要点：

核心对象是报修工单。学生、宿舍、故障信息、派工记录、维修员、维修反馈和评价都围绕工单展开。工单也是状态图、数据流和测试设计的主线。

## 3. 为什么使用 DFD？

回答要点：

DFD 能清楚表达外部实体、处理过程、数据存储和数据流。宿舍报修系统涉及学生、管理员、维修员、后勤部门之间的信息传递，因此适合用 DFD 描述业务流转。

## 4. 顶层 DFD 和 0 层 DFD 有什么区别？

回答要点：

顶层 DFD 主要说明系统边界，把整个系统看作一个处理过程；0 层 DFD 将系统进一步分解为报修受理、工单审核、派工处理、维修反馈确认和统计查询等主要加工。

## 5. DFD 如何转换为系统结构图？

回答要点：

0 层 DFD 中的主要加工可以转换为系统一级功能模块。例如报修申请受理对应报修申请管理模块，工单审核和派工处理对应工单审核与派工模块，统计查询对应统计报表模块。

## 6. 工单状态图体现了什么？

回答要点：

状态图体现报修工单从提交到完成的生命周期。不同状态之间的转换由学生提交、管理员审核、派工、维修员反馈和学生确认等事件触发。

## 7. 为什么详细设计选择报修申请受理模块？

回答要点：

该模块是整个系统的入口，包含必填项校验、宿舍档案匹配、附件检查、紧急程度判断和工单生成等逻辑，既有顺序结构，也有分支和循环，适合展示详细设计和测试设计。

## 8. 白盒测试和黑盒测试分别覆盖什么？

回答要点：

白盒测试关注程序内部逻辑路径，例如语句覆盖、判定-条件覆盖、条件组合覆盖和独立路径覆盖。黑盒测试从输入输出角度设计有效/无效等价类和边界值，不依赖内部代码结构。

## 9. 如何保证报告中各图表一致？

回答要点：

所有图表都围绕报修工单展开。类图中的对象对应数据字典，DFD 中的数据存储对应核心对象，结构图来自 0 层 DFD，加工逻辑又对应详细设计和测试用例。

## 10. 系统后续可以怎么扩展？

回答要点：

可以增加移动端消息提醒、维修材料管理、维修员绩效统计、满意度分析、超时预警和报修知识库等功能。扩展时仍然应围绕工单状态和数据流保持设计一致。
