# 演示流程脚本

本文档用于答辩现场演示。由于本作业是软件工程设计报告型作业，演示重点放在报告结构和设计链路上。

## 1. 演示前准备

准备材料：

- 正式报告：`../宿舍报修管理系统软件工程导论期末考查报告.doc`
- PDF 版本：`../宿舍报修管理系统软件工程导论期末考查报告.pdf`
- 快速答辩稿：`../答辩.md`
- 本目录辅助文档

建议提前打开：

1. 报告目录页。
2. UML 类图。
3. 顶层 DFD 和 0 层 DFD。
4. 工单状态图。
5. 系统结构图。
6. PDL 伪代码和测试用例部分。

## 2. 开场介绍

建议 30 秒说明：

“我的选题是宿舍报修管理系统，面向高校宿舍维修管理场景。项目目标是把学生报修、管理员审核派工、维修员处理反馈、学生确认评价和后勤统计形成规范流程。本报告重点展示软件工程各阶段方法，以及这些方法如何围绕同一条业务主线展开。”

## 3. 演示步骤

### 步骤一：说明选题背景

展示报告的项目背景和需求概述。

讲解点：

- 报修渠道分散。
- 进度不透明。
- 派工和反馈难追踪。
- 后勤统计效率低。

### 步骤二：展示参与者和业务流程

讲解学生、管理员、维修员、后勤部门四类参与者。

可说的话：

“这个系统的核心是工单在多个角色之间流转，最终形成可追踪、可统计的闭环。”

### 步骤三：展示 UML 类图

讲解点：

- 学生和宿舍关联。
- 报修工单是核心对象。
- 工单关联派工记录、维修员和评价记录。

### 步骤四：展示 DFD

先讲顶层 DFD，再讲 0 层 DFD。

讲解点：

- 顶层 DFD 说明系统边界。
- 0 层 DFD 把系统拆为报修受理、审核、派工、反馈、统计。
- 数据流和数据存储支撑后续结构设计。

### 步骤五：展示工单状态图

讲解点：

- 待审核、已派工、维修中、待确认、已完成等状态。
- 状态变化由不同角色动作触发。

### 步骤六：展示总体结构图

讲解 DFD 如何转换为系统模块。

可说的话：

“结构图根据 0 层 DFD 中的主要加工转换得到，这体现了从需求分析到总体设计的衔接。”

### 步骤七：展示详细设计和测试

重点讲报修申请受理模块。

讲解点：

- 输入校验。
- 宿舍档案匹配。
- 附件检查。
- 紧急程度判断。
- 工单生成。
- 白盒和黑盒测试如何覆盖该模块。

## 4. 收尾总结

建议 30 秒总结：

“本报告围绕宿舍报修这一条主流程，完成了需求分析、数据建模、数据流分析、总体结构设计、详细设计和测试设计。各图表和测试用例都围绕报修工单展开，保证了软件工程设计的一致性。”

## 5. 备用方案

如果现场无法打开 Word/WPS：

1. 使用 PDF 版本展示。
2. 使用 `../答辩.md` 作为口头讲稿。
3. 按本文件的步骤讲解，不依赖动态演示。
