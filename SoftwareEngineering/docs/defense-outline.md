# 答辩提纲

本文档可用于制作 PPT 或组织口头汇报。建议 8 页左右，汇报控制在 5 到 7 分钟。

## 1. PPT 结构建议

### 第 1 页：项目标题

标题：宿舍报修管理系统软件工程设计

内容：

- 课程：《软件工程导论》
- 选题：高校宿舍报修管理
- 汇报人、班级、日期

### 第 2 页：项目背景

内容：

- 报修渠道分散。
- 维修进度不透明。
- 派工记录难追踪。
- 后勤统计依赖人工整理。

讲解重点：

“选题来自高校宿舍生活中的真实事务管理场景，流程清晰，适合展示软件工程设计方法。”

### 第 3 页：系统目标和角色

内容：

- 学生提交报修。
- 管理员审核派工。
- 维修员处理反馈。
- 学生确认评价。
- 后勤统计分析。

### 第 4 页：需求分析成果

内容：

- 主要功能模块。
- 核心数据对象。
- UML 类图。
- 数据字典。

### 第 5 页：数据流分析

内容：

- 顶层 DFD。
- 0 层 DFD。
- 外部实体、加工、数据存储。

讲解重点：

“DFD 用来说明业务数据如何在角色、处理过程和数据存储之间流动。”

### 第 6 页：总体设计

内容：

- 系统结构图。
- 工单状态图。
- DFD 到结构图的转换。

### 第 7 页：详细设计与测试

内容：

- 报修申请受理模块。
- PDL 伪代码。
- 程序流程图 / N-S 图。
- 白盒测试和黑盒测试。

### 第 8 页：总结

内容：

- 完成了软件工程主要阶段设计。
- 核心主线围绕报修工单。
- 不足与后续扩展：移动端提醒、维修材料管理、满意度统计等。

## 2. 口头汇报版提纲

1. 我的选题是什么。
2. 为什么这个场景需要信息系统。
3. 系统有哪些角色和主流程。
4. 需求分析阶段产出了哪些模型。
5. DFD 如何转换为系统结构。
6. 详细设计选择了哪个模块。
7. 如何设计测试用例。
8. 总结设计一致性和后续改进。

## 3. 3 分钟压缩版

1. 背景：宿舍报修线下流程分散，进度和统计不方便。
2. 目标：形成提交、审核、派工、维修、确认、统计闭环。
3. 方法：用类图描述对象，用 DFD 描述数据流，用状态图描述工单生命周期。
4. 设计：由 0 层 DFD 转换系统结构图，详细设计报修受理模块。
5. 测试：对白盒路径、条件组合和黑盒等价类/边界值进行设计。
6. 总结：报告体现了软件工程从分析到设计再到测试的完整过程。
